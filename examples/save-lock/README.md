# 存檔與編輯鎖最小範例

只用 Univer **開源套件**，示範「不做即時協作」時的基本做法：

- 試算表編輯（開源的 Sheets 核心、篩選、排序、尋找取代、條件式格式、資料驗證）
- 把活頁簿 JSON 快照存到後端
- **編輯鎖**：同一份活頁簿同時只有一個人能編輯，其他人以唯讀開啟，並看到誰正在編輯
- **版本號檢查**：存檔時比對版本，避免舊內容蓋掉新內容

## 啟動

```bash
pnpm install
pnpm --filter univer-examples dev:save-lock
```

開啟 <http://localhost:5174/>。網址可以加 `?id=任意英數代號` 開不同的活頁簿，例如 `?id=budget-2027`。

要模擬兩個人，請用兩個不同的瀏覽器（或一般視窗加無痕視窗）開同一個網址：

1. 第一個視窗會拿到編輯鎖，徽章顯示「編輯中」。修改後按「存檔」或 `Ctrl+S`。
2. 第二個視窗顯示「唯讀：某某 正在編輯」，無法修改。
3. 關掉第一個視窗後，第二個視窗約 5 秒內會提示可以重新載入，重新載入後就能取得編輯權。

> 同一個瀏覽器的兩個分頁也可以，因為 client id 以分頁為單位（`sessionStorage`）。

## 檔案

| 檔案 | 說明 |
|---|---|
| `main.ts` | 前端：建立試算表、取得與續約編輯鎖、唯讀模式、未存檔偵測、存檔 |
| `api.mjs` | 後端 API（只用 Node 內建模組），可掛在 Vite 或任何 Node HTTP 伺服器上 |
| `server.mjs` | 單獨執行後端：`pnpm --filter univer-examples server:save-lock`（預設 port 3030） |
| `vite.config.ts` | 開發伺服器設定，把 `api.mjs` 掛成中介層，一個指令同時啟動前後端 |
| `.data/` | 存檔資料（每份活頁簿一個 JSON 檔），已加入 `.gitignore` |

## API

| 方法與路徑 | 用途 | 主要回應 |
|---|---|---|
| `GET /api/workbooks/:id` | 讀取快照、版本號、目前誰在編輯 | `{ version, snapshot, savedAt, savedBy, lock }` |
| `POST /api/workbooks/:id/lock` | 取得或續約編輯鎖，body：`{ clientId, userName }` | 200 成功；423 已被別人鎖住 |
| `POST /api/workbooks/:id/unlock` | 釋放編輯鎖，body：`{ clientId }` | 200 |
| `PUT /api/workbooks/:id` | 存檔，body：`{ clientId, baseVersion, snapshot }` | 200 成功；423 沒有持有鎖；409 版本衝突 |

## 編輯鎖規則

- 鎖的有效時間 30 秒，前端每 10 秒續約一次。
- 關閉或離開頁面時，前端用 `navigator.sendBeacon` 主動釋放鎖；瀏覽器當掉或斷網時，最多 30 秒後鎖自動失效。
- 如果電腦休眠太久、鎖被別人拿走，前端會切成唯讀並提示，尚未存檔的修改無法再存回去。
- 存檔需要同時滿足：持有鎖，且 `baseVersion` 等於伺服器目前的版本。

## 正式上線前要補的部分

這是用來評估可行性的最小範例，正式使用前至少要處理：

1. **身分驗證**：目前使用者名稱由前端自己填，`clientId` 也沒有綁定登入身分。要改成從登入 session 取得使用者，並檢查該使用者有沒有權限開啟或編輯這份活頁簿。
2. **鎖存放位置**：鎖放在 Node 行程的記憶體，重啟就消失，也無法跨多台伺服器。多台部署時改放 Redis 或資料庫。
3. **資料儲存**：目前存成本機 JSON 檔，正式環境改存資料庫或物件儲存，並保留歷史版本以便還原。
4. **自動存檔**：目前只有手動存檔。可以在偵測到修改後延遲數秒自動存檔，降低忘記存檔的風險。
5. **管理員強制解鎖**：有人開著頁面離開座位時，需要讓管理員或檔案擁有者能強制釋放鎖。
6. **Excel 匯入匯出**：開源版不含 XLSX 轉換，需要的話要另外處理。
